# Support multiple API instances

DANS must support deployments with multiple API instances from its first release, sharing authorization and audit state in PostgreSQL while proxying one PowerDNS upstream. PostgreSQL 16 through 18 on their current minor releases are supported; PostgreSQL is the only state engine. DANS uses native `pgx/v5` pooling and `sqlc`-generated checked-in queries, while embedded forward-only migrations run only through a separately invoked, locked CLI command using a DDL role. API instances use a DML-only role and become unready on an incompatible schema rather than migrating at startup; they remain fail-closed and never queue, automatically retry, or fail over ambiguous mutations.

V1 supports coordinated upgrades rather than mixed-version rolling upgrades: operators back up PostgreSQL, drain every DANS instance, run the target binary's migration, and start only that target version. Binary downgrade after a migration is unsupported. This may briefly stop the management API without interrupting authoritative DNS. Integration QA runs two same-version DANS instances and exercises the oldest and newest supported PostgreSQL majors against PowerDNS 5.1.3, including cross-instance revocation and dependency-failure behavior.
