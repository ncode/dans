# Authorize whole RRsets with name patterns

DANS delegations are immutable, operator-defined, allow-only grants combined by union across an identity and its groups. A grant selects canonical absolute owner names with tagged exact or Route 53-style glob selectors plus optional record-type and change-kind restrictions; matching grants authorize the whole RRset and therefore permit `REPLACE`, `DELETE`, `EXTEND`, and `PRUNE`, but literal wildcard RRsets and the zone apex require exact selectors. DANS evaluates current authority for every request, authorizes every member before forwarding one batch, and rejects the whole request if any member is forbidden. This avoids per-value ownership, deny precedence, and batch splitting while supporting individual-value PowerDNS operations and every RR type, including PTR.

Policy remains relational in PostgreSQL. Each authorization class uses one primary-database decision statement; the delegated-write statement expands a bounded canonical batch, unions direct and group grants, matches exact selectors or creation-time escaped SQL `LIKE` patterns, and requires every tuple to match. Selectors and optional type/action filters are rows rather than JSON policy blobs. DANS does not introduce a regex engine, PostgreSQL RLS, stored procedures, or database extensions.
